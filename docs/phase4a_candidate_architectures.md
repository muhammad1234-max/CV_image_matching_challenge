# Three ways to address the same false merge

The decision is whether to keep a geometric connection, how that changes scene assignment, and which poses the mapper can recover afterward. All three consume opaque inference data. Scene labels used in later evaluation are unsuitable as inference inputs. An invalid relative pose within one scene and a valid-looking match between different scenes require different targets.

| Candidate | Intervention and supervision | Practical constraint | First question |
|---|---|---|---|
| A, primary | A rotation-consensus test can veto a connection across a proposed normalized cut. No fitting. | Needs calibrated two-view rotations on both sides and across the cut. | Do separate crossing camera pairs disagree about one frame alignment? |
| B | Learn the probability that verified endpoints belong to the same scene. Train on disjoint source groups. | Very few independent training groups; many correlated edge labels. | Does it outperform an inlier-count control on held-out source groups? |
| C, fallback | Compare predictive reprojection error of a merged model and provisional split models on held-out observations. No fitting on scene labels. | Needs tracks, cameras and at least one additional reconstruction. | Can independent observations discriminate partitions at comparable coverage? |

## A. A boundary test before reconstruction

Input verified endpoints, inlier counts, intrinsics and valid calibrated camera-to-camera rotations. Build a weighted graph, propose a connected bipartition, estimate each side’s frame using only internal pairs, and test whether several endpoint-disjoint crossing rotations can agree on a single alignment. If the sides pass their own checks and cross-side consensus is below half, remove crossing associations and let the pinned mapper estimate poses. See the exact objective, tensor contract and complexity in the mathematical formulation and selected architecture.

Output a pair mask, abstention reason, and ordinary per-image ns64 predictions. No supervision, loss or optimizer. The two archived endpoint lists support topology debugging only. Requires a new auditable geometry export. Engineering estimate 3–5 days to qualify the adapter plus 1–2 days for the CPU prototype. The attraction is little incremental GPU cost and an explicit abstention case. Weak overlap, coherent repeated structure, wrong intrinsics, drift in a reference tree or an incorrect first cut can defeat it. Closest geometric alternatives are Gong and Xu. Falsify first with known rigid, corrupted and coherently aliased synthetic graphs; then use the single predefined Haiper development run to measure whether the proposed cut even exposes conflicting rotations. If the mechanism cannot act, keep the negative result.

## B. Supervised edge reliability followed by partitioning

Build one row per verified pair. Use log inlier count, normalized inlier fraction, image-plane coverage per side, median Sampson error, two endpoint degrees, shared-neighbor fraction, median valid triangle rotation closure, descriptor retrieval score and its availability mask. Symmetrize endpoint channels via min/max. Add one missingness flag per numeric channel; standardize with training-only statistics. A shared two-layer 32-unit ReLU MLP maps each edge row to 32 channels; concatenate that vector with the symmetric mean and absolute difference of the two endpoint neighborhood mean vectors, then use a 32-unit head and sigmoid. Each edge receives one round of incident-edge information without materializing the line graph. Output probabilities and final partitions. Initial objective is a signed multicut with costs log(p/(1-p)) for cutting edges, probabilities clipped to [0.01,0.99]. Deterministic greedy additive edge contraction of positive aggregate costs, followed by one increasing-ID single-node local-improvement sweep. Send resulting within-partition edges to the same mapper. Complexity O(E d²) for width d and roughly O(E log E) for sparse contraction with implementation-dependent updates; memory O((N+E)d).

Teacher, on administrative training groups only: positive = both non-outlier endpoints in the same annotated scene; negative = two different non-outlier scenes. Exclude edges incident to a labeled outlier from this loss; handle image outliers through registration. Do not call every within-scene pair geometrically correct. Fit group-balanced, class-balanced BCE with AdamW, lr 0.001, weight decay 0.0001, 40 epochs fixed, seed 20261111; full small graphs, one optimizer update per training graph. Weight groups equally across an epoch, stratify positives/negatives within each graph, skip single-class graphs for balanced updates and disclose lost groups. If either class absent globally, stop. Temperature-scale on a separate calibration group by unweighted NLL, equal weight per dataset, score Brier and 10-bin reliability with group counts. Freeze normalizer, calibration and all weights with the model.

Out-of-fold only: A evaluated from B-trained weights and vice versa, exclude duplicate-linked sources as units. For the four-pilot experiment additionally exclude all four pilot source groups from fitting and calibration across branches; partition the remaining training-side groups by lexical source ID, reserve the last for calibration. Stop if this leaves fewer than two fitting groups with usable cross-scene negatives or one independent two-class calibration group. External pretrained overlap is separately disclosed. Fit/export in an environment physically separate from the label-free worker. Estimated 3–6 engineering days beyond the adapter and minutes to an hour of CPU fitting for small cached graphs. Gains could come from learned nonlinear combinations; domain transfer and label imbalance are severe. A permutation test within source group and a frozen logistic model on log-count/degree are cheaper falsifiers than a larger GNN. Damblon, Doppelgangers++, MVDG and XDG constrain novelty. A gain from a trained head alone would be an application result.

## C. Held-out reprojection feedback after tentative mapping

Use the same topology-only split proposal. Deterministically reserve 20% of image observations by a hash of opaque image ID and canonical keypoint ID before triangulation or pose fitting. Fit both hypotheses to identical remaining observations: one original component and two side-restricted incremental reconstructions. For a candidate held-out observation predict its pixel location using its camera, an independently triangulated track with at least two other training views, and a track association obtained solely from retained pair indices. Never triangulate using the held-out pixel. Score a fixed list of held-out observations under both hypotheses. Use capped pixel error min(10, ||x−project(X)||) / 10, assigning 1 to an unregistered, unmapped, behind-camera or unprojectable observation. Require at least 50 eligible held-outs from at least six cameras on each side, selected before comparing residuals. Use equal per-camera means then equal side means. Accept a split only for a loss decrease of at least 0.10 and no decrease in number of registered cameras; otherwise keep the original. Refit the chosen hypothesis on all original observations for final poses. Group membership never enters the inference contract.

Outputs include partition, coverage, paired residuals, missing prediction counts, BA time and final poses. No learned weights. Engineering estimate 5–10 days beyond the adapter; one merged and up to two local trial maps plus a final map per tested component. Runtime and memory depend on track count, visibility and sparse BA fill-in. Reuse matching bytes, stream the two side fits sequentially; measure maximum resident memory. Repeated structure may fit perfectly under both hypotheses. Holding out pixels does not remove all dependence if original matching used those pixels; describe it as a reconstruction holdout. Closest prior work is Gong, Xu, HiSfM and incremental BA. Budget alternative: screen one cached ambiguous component only, with a known rigid negative control. Reject if validation favors missing projections, split proposals lack support, or CPU mapping exceeds twice the matched control wall budget. If A lacks rotations and C lacks tracks, stop at a feasibility report.
