# Clean-GPU execution and recovery

The local cache audit verified the 18,407,424-byte Haiper parent by SHA-256 and logical table records. The four ns64 development workers, the two Haiper branch returns and the collected 4G/4G.1 returns have no reusable original/trial indexed exports. The previous workspace search covered 104 archives including 27 nested. Organizer caches use a different matcher. A 313,857,668-byte opaque Dioscuri/Baalshamin image archive passes the exact ordered-content fingerprint; it contains no matches. FBK Vineyard needs an image export. See reports/phase4i/inventory.json for individual hashes and availability.

**Observed costs.** Haiper pass-through and active mapping took 448 and 380 seconds with 767,288 and 734,516 KiB peak mapper RSS. The 76-image ns64 worker took 36.07 minutes including 21.62 minutes mapping. A free Stairs VM had about 11.24 GiB cgroup RAM and 1.11 GiB remaining at abort. The Theater/Church attempt had 2,405 seconds after setup. Neither yielded a parent. The largest historical pilot GPU allocation was about 5.60 GiB and maximum process RSS about 6.49 GiB. These measurements cover different jobs and scopes.

**Scheduling estimate.** Historical image- and pair-scaled scenarios for the 138-image reference are about 65–120 minutes; an additional map and export can take substantial time. Budget at most 90 minutes for one trial, four hours for a session including setup, and reserve 20 minutes for export. Across resumed sessions, completed stage times debit the same four-hour dataset budget. Each fresh capture requires at least 140 minutes remaining after setup. Existing worker checks require at least 8 GiB host available and 9,412,018,176 bytes free GPU at start. Its staged reserves also apply. cgroup/host margins, GPU free-memory margins, pressure and OOM events use the 4G.1 sampler. Summed RSS, PSS, USS and GPU device memory have distinct meanings. Free Colab’s session lifetime and memory cannot be assumed from the T4 label. No live eligible GPU allocation was verified for Phase 4I.

**Instructions after supervisor authorization**

1. Start a fresh free Colab T4 runtime, leave Drive unmounted, and upload notebooks/step04i_final_candidate_colab.ipynb through File → Upload notebook. Run its first three cells in order. Supply imc_ns64_clean_runtime.zip in the first upload. These cells bootstrap the pinned runtime, fetch/verify the assets and check dependencies. Setup requires internet.
2. Run cell 4 with the default 138-image dataset. Upload imc2024_dioscuri_baalshamin_opaque.zip and enter the actual remaining session seconds. Use only the notebook and allowlisted inputs in this runtime. Keep the review ZIP, mappings, organizer results and labels on the administrative machine.
3. Run cells 5–8 in order. Capture executes retrieval/matching/verification and snapshots the post-pruning numerical parent at the mapper boundary. The verified parent is the reusable checkpoint for completed matching; progress logs inside unfinished matching cannot resume a partially computed match. Original runs unchanged mapping and saves its predictions and indexed measurements. Trial evaluates at most one proposed boundary on an audited clone. Decision selects the branch from sealed outputs on the pinned runtime. Each cell downloads a dataset/stage ZIP and prints its SHA-256. Save both before disconnecting. An intercepted mapper call in the capture worker intentionally exits after snapshot; the mapper runs in the following cell.
4. Across a VM reset, repeat setup and upload the same opaque input. Using Colab’s Files pane, put **each previously completed stage ZIP**, under its original name, in /content before running its cell. Enter the original separately saved hash when prompted. Run stage cells in order. Restoration verifies the complete chain and skips finished computation. One original and one attempted trial per group; preserve timeout/failure evidence. An interrupted mapper has no within-mapper restart. An expired stage without a final seal requires review before repeating.
5. For the second group, use the project’s frozen step03c_full_ns64_kaggle_export.ipynb with BATCH=['fbk_vineyard'] to produce fbk_vineyard_opaque.zip on the administrative/export side. Use a fresh inference VM and change only the dataset line in cell 4. Stop after these authorized groups. Administrative scoring is described in phase4i_evaluation_protocol.md.

If a verified capture or original fails, preserve the failure ZIP. If a bounded trial fails, the trial receipt records the error and the final selector uses the original bytes. Digest mismatches on restored stages invalidate the run. Remaining time at preflight is an operator-supplied upper bound. No paid instance or new GPU job was launched in this review.
