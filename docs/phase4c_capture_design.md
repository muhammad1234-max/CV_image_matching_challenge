# Phase 4C capture design

At the pinned incremental_mapping entry in pipelines/imc2025_pipeline.py, after verification and optional pruning, hook.py opens a read transaction, fingerprints all schema and table records, performs a WAL-aware SQLite backup and checks logical equality and integrity. The finalized database is named by SHA-256. The original stays read-only. The adapter rejects unexpected pruning, localization or configuration paths. Actual image and camera IDs, all 54 image hashes, dimensions, camera parameters, solver, ordered raw/verified index blobs, F/E/H and optional qvec/tvec are captured. Pre-writer xy hashes check the +0.5 offset exactly once. The verifier’s own inliers are checked against the mapper database. Original identity mappings and scoring data stay on the administrator machine.
