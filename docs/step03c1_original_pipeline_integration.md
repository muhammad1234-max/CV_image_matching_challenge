# Original pipeline integration

The selected configuration creates IMC2025Pipeline via pipeline.create_pipeline. Its run method uses create_data_dict and runs each image collection through run_scene. The ensemble combines ASMK, retrieval SPoC, DINOv2 and ISC. run_point_tracking_matching_stage uses mast3r_hybrid v2, including ALIKED and Magic Leap SuperPoint keypoints. import_into_colmap writes keypoints and match indices. verify_matches uses COLMAP's default verification branch. incremental_mapping runs with one mapper thread, min_model_size 3 and max_num_models 25. get_reconstructions assigns model IDs and world-to-camera poses. results_to_submission_df materializes scene assignments including outliers.

ns64_adapter.py takes an ETs image directory, a new workspace, the reviewed YAML and a verified alias map. It stages images under opaque names in a private test/ETs tree, constructs IMC2025TestData from neutral rows and calls the original pipeline. Immutable identity mapping restores the original names for sorted output. The adapter checks membership, valid rotations, translation and outlier NaNs before committing predictions. A separate process runs the frozen development evaluator on the final CSV. The real upstream pipeline and GPU measurements remain untested. This internal adapter is for a future validated worker. ets_worker.py verifies a successful matching manifest/receipt, creates a fresh attempt workspace, applies an 1800-second shared inference/scoring deadline and retains lightweight evidence on failure. Interrupted model stages have no validated replay protocol. Retry in a fresh workspace. End-to-end acceptance on Linux remains outstanding.
