# Phase 4B decision for supervisor review

**CPU prototype complete.** Candidate A removed the deliberately incompatible synthetic boundary and retained the rigid, mildly noisy and coherently aliased fixtures. It abstained with too few distinct cameras, insufficient loop closure, missing rotations or a degenerate spectral direction. The coherent-alias result illustrates a fundamental blind spot: mutually consistent false rotations can describe one plausible frame. There is no new real-dataset metric.

| Supervisor question | Verified result |
|---|---|
| What changed? | New CPU package under src/novel_model/geometry_graph_v1, one prototype YAML referencing the Phase 4A proposal digest, a pytest module, two inventory/profile scripts, seven Phase 4B documents, reports and review ZIP. The ZIP manifest enumerates the files. |
| How does it decide? | On each original verified component, use log1p(actual inliers) and one connected normalized-cut proposal with at least six nodes per side. Use two maximum-weight internal rotation trees and non-tree closure checks. Four checks per side and 80th percentile ≤10° are required. Test at least six and at most 32 distinct-endpoint crossing rotations against the best observed frame alignment. Split only below half consensus. The exact tolerance and tie policies come from the frozen proposal. |
| How is it isolated? | Strict allowlisted graph payload, opaque IDs, externally pinned source/configuration/membership/parent and byte digest. Rotation masks and conventions are explicit. The default retains the graph. Serialized edge masks bind to the parent and configuration, and a future consumer can reject reordered or corrupted masks. |
| What did the controls do? | On the 64-edge contradiction fixture, pass-through, normalized-cut, triangle, per-edge-consensus and Candidate A removed 0, 8, 0, 7 and 8 edges. Topology-only cutting also splits the rigid control. True and false triangles require geometry to distinguish. |
| What passed? | 70 new pytest cases and 163 existing tests; 233 passed. This includes SO(3) validity, reversed orientations, left/right gauge changes, unique-boundary camera renumbering, disconnected and isolated nodes, deterministic ties, exact half consensus, corruption rejection, sparse eigensolver, comparator behavior and CLI/mask replay. |
| What did it cost? | 14.11 to 152.67 ms median for 22–225 synthetic cameras on this CPU. Largest case had 1,631 edges and a 70.3 MiB process peak working set. Decoding and validating the payload cost more than the spectral proposal. |
| Can the old caches drive the model? | Haiper (454 pairs) and Theater/Church (616) import as topology-only graphs. ETs and stairs have aggregate pair counts only. The four sets lack actual per-edge inlier counts, usable pair rotations, intrinsics, indexed inliers and a mapper-ready ns64 database. Final per-camera predictions are historical outputs. |
| Is the benchmark intact? | The project validator passed frozen membership/integrity checks; nine Phase 4A reference-file pins matched. All four original archive hashes matched. All 1,810 ns64 source-snapshot files matched the pinned manifest. No new full-development or 138-image ns64 result was registered. |
| Ready for a Haiper GPU test? | Ready for a supervisor decision on a bounded **capture and pass-through integration**. The CPU package is not a drop-in mapper adapter. Capture/recovery and pass-through parity are outstanding. An active Haiper score cannot be obtained from the existing archives. |

**Next experiment if approved.** On the original 54 Haiper images in neutral order 20261111, capture a read-only parent after verification/pruning and before mapping. Preserve indexed geometry, actual per-pair support, original camera IDs/intrinsics/coordinate conventions, stage hashes and trusted source/environment. Verify calibrated rotations or recover them under the predeclared quality gates. Schedule one matched pass-through check. Only then assess active A against the same parent and frozen organizer/ns64 comparisons, keeping all abstentions and failures. Haiper has already influenced the hypothesis and is a development pilot. Phase 4B stopped before GPU inference or reconstruction.
