# Phase 2A validation strategy
PROJECT-WIDE REQUIREMENT: every improvement uses the same frozen reproducible baseline and validation split. AGENTS.md persists this rule. No real split or baseline has been frozen yet: metadata and the duplicate audit are missing.

Primary design: hold out entire datasets, preserving their complete mixtures of scenes and outliers for joint clustering/reconstruction. Deterministic seed 20261111 assigns approximately 20% of dataset groups to locked confirmation, 20% to development, and the rest to training (at least one each; fewer than three groups is an error). This is a draft allocation policy, not proof of sufficient statistical power. Input SHA256, seed, assignments and split SHA256 are saved. Reordering input leaves dataset assignment stable but changes the input/split artifact hash. Existing output directories cannot be silently overwritten.

Before freezing, validate unique IDs and CSV completeness; audit shared provenance, exact hashes and near-duplicate images across datasets. Merge related groups before assignment where necessary and review scene/domain coverage without using model scores. The current generator does not implement cross-dataset duplicate discovery; its output is explicitly DRAFT_REQUIRES_DUPLICATE_GROUP_AUDIT. No image-pair random split is permitted. Training excludes development/confirmation images, their pairs, labels and poses. Validation poses stay evaluator-only. Hidden test labels never enter training or selection.

Secondary scenario: a separately frozen scene-disjoint development split can diagnose within-domain generalization, only after provenance/near-duplicate grouping. Preserve several scenes plus outliers in each evaluation collection; never split a scene across training and validation. This scenario is designed, not implemented, because real metadata is absent. It cannot replace the dataset-held-out primary comparison.

Small scenes: retain them in full-dataset scoring under the verified evaluator; report counts, registration failures and coverage separately. Fewer than four valid cameras cannot support the reference's three-camera subtraction meaningfully. Do not drop difficult scenes post hoc. Any minimum-size diagnostic subset must be frozen before experimentation and labeled exploratory.

Freeze a benchmark version containing baseline commit, configuration, weight hashes, environment lock, input manifest, split manifests, evaluator hash/settings, threshold metadata and seed. Only then compare each improvement with that same baseline. Necessary corrections create a new version and require rerunning all compared methods. Tune only on development; confirmation is a locked final check, not an iterative tuning source. Record all attempted variants, paired per-dataset differences, macro aggregate, runtime, peak resources, failures and uncertainty across independent datasets. Do not infer significance from a single leaderboard change.

Metric provenance: official prose specifies mAA-first scene assignment and harmonic clustering/pose fusion; the saved participant code uses overlap-first assignment. Keep these versions explicitly separate. Participant-reference mAA/clusterness/joint score are local reference metrics until official parity is established. Registration coverage, cluster diagnostics and graph statistics are exploratory proxies. Do not silently alter assignment or invent thresholds. Actual train_thresholds metadata is unavailable. See step015_metric_reconciliation.md and https://www.kaggle.com/competitions/image-matching-challenge-2025-ongoing/overview/evaluation.

Actual split manifests: NOT CREATED. Synthetic generation only is tested. This avoids falsely freezing a data-dependent protocol before the real data and leakage checks exist.
