### Proposed decision rule

On the verified graph propose one normalized cut per connected component with at least six images per side. Compute a frame from internal calibrated rotations on each side. At least four non-tree checks per side must support the frame (80th percentile error ≤10°). A crossing pair predicts frame alignment Q = Uⱼᵀ Rⱼᵢ Uᵢ. Select 6–32 crossing pairs with no shared endpoints. Count the most pairs compatible with any one observed alignment, with radius max(15°, twice the sum of the two internal residual quantiles). Split only if even that center explains strictly fewer than half of them. Insufficient evidence retains all edges. Map with frozen options and export actual camera poses. A coherent alias can pass this test, and a bad internal tree can create a false split. Rotational consistency is a necessary condition only. ### Cost, scope and evidence required for advancement

The four original workers took 77.2 minutes together. An initial four-dataset capture and one additional map per dataset would take about 115 worker minutes if historical times hold, excluding setup, transfer and scoring. The measured T4 GPU peak was 5.60 GiB allocated; peak RSS was 6.49 GiB. Full development capture alone has two extrapolated scenarios of roughly 12–30 T4-session hours. Campus or paid GPUs are unnecessary for the first coding milestone. Archive scans found verified endpoints on Haiper/Theater but no replayable ns64 match database or signed relative poses on the four. A checked new capture is a dependency. [Cost model and cache requirements](phase4a_implementation_plan.md)

1. Validate synthetic camera graphs and a read-only feature inventory. Require parity with a mask-disabled comparator. Freeze all decisions before the first real intervention.
2. Run Haiper first after approval. It has measurable cross-scene support. A no-op or unsupported proposal is an informative stop. Use the same four fixed datasets for paired comparisons if it passes; retain Haiper once.
3. Ablate spectral split alone, local cycle pruning, per-edge consensus pruning, endpoint disjointness, uncertainty radius, internal checks and minimum support. Compare both ns64 and organizer and disclose ETs order sensitivity. Measure mAA, clusterness, combined, merge/split and outlier errors, camera coverage, time, CPU/GPU peaks and failed attempts.
4. Expand only on a positive mean paired gain over the matched control, a corrected merge, no new false splits on ETs/Theater, no more than one lost inlier registration in total and at most 25% aggregate wall overhead. Report both development folds on the original 11 datasets. Protected confirmation requires the locked method and a separate release; the four pilots already informed the hypothesis.
