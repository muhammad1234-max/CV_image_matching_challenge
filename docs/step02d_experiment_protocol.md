# Experiment and immutable baseline protocol

> Update after metadata receipt: **FROZEN**. All three original CSV hashes match the prior audit; full image membership and all hard constraints pass. The earlier draft/missing-input descriptions below are historical and superseded by `step02d_metadata_freeze_review.md`. No Phase 3 run is authorized by this freeze.


`experiment_template.json` intentionally contains nulls: it is not a completed experiment. `benchmark_contract.validate_experiment` rejects draft benchmarks, missing SHA256 pins, missing runtime/metrics, incomplete per-dataset coverage and missing baseline references. `register_experiment.py` writes exclusively into separate `experiments/baseline/` and `experiments/improvement/` directories. Existing IDs cannot be overwritten. The original comparator remains immutable.

Phase 3 registration requires exact benchmark version/hash, Git commit (or explicit unversioned status plus a complete source snapshot hash), dataset inventory/split/evaluator/threshold hashes, model configuration hash, each weight hash, environment/dependency versions and lock/container hash, random seeds, wall runtime, per-dataset mAA/clusterness/combined score, registration coverage, failure counts and submission-format check results. Record CPU/GPU peak memory as `{measured,value,reason}`; unavailable is null with a reason, never a fabricated zero. Include hardware, CUDA, driver and pipeline-stage runtime details in environment/runtime supplementary records. Every random library receives recorded seeds; document nondeterministic kernels rather than promising bitwise GPU equality.

The first successful full development baseline is registered only after both folds finish, failures are included, all contracts pass and the exact code/config/weights/environment are archived. Register per-fold records and a supervisor-approved index linking both immutable experiment IDs and their content hashes. A smoke test is not a baseline. Primary aggregate is the equal mean of 11 paired dataset differences, with per-dataset components, runtime differences, failures and memory reported alongside. `paired_comparison` rejects changed benchmark components, reference IDs, partitions, seeds or environments. Environmental changes require a separately controlled baseline rerun.

Improvement experiments reference that baseline and change only the declared intervention. Keep ablations and sensitivity evaluator results separate. Matching benchmark hash includes both original evaluator hash and adapter hash. Any correction to splits, data, thresholds, evaluator, comparator or environment requires explicit versioning and rerunning all methods in the comparison. A new high leaderboard value is not evidence of a local improvement.

Confirmation records require a recorded `confirmation_release_id` after supervisor approval and selection lock. That is an audit requirement, not an authorization service. No confirmation result may drive hyperparameter/model selection. Failures remain in the evaluation population. If a confirmation failure requires methodological changes, record the limitation and define a fresh confirmation policy with the supervisor; do not silently reuse the held-out labels.
