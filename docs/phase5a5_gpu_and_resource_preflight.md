# Phase 5A.5 gpu and resource preflight

Kaggle previously exposed two Tesla T4 devices of 15,360 MiB each, both idle, driver 580.178.04. The smoke adapter selects physical index zero by GPU UUID before any child imports torch. The CUDA probe asserts one visible T4, performs a tensor calculation with known result, synchronizes, measures peak allocation and checks allocation returns to zero after release. Model loaders inherit the same device mask. Subprocess sampling checks GPU process placement where the driver exposes process records.

The earlier host sample had a 30 GiB cgroup limit, 0.79 GiB charge and about 19.5 GiB free working disk. The adapter uses the frozen host/cgroup, OOM-event, pressure and GPU guards and process-tree PSS. It samples scratch space around expensive subprocesses. Disk planning scales the historical 18,407,424-byte 54-image parent by possible pair count to 121,597,050 bytes at 138 images. Allowances include the sealed parent, three SQLite copies, two reconstructions, observations, archive, restore copies and export reserve, about 6.79 GiB after setup. This is an estimate. Actual matching intermediates and parent size are unknown. Available scratch and output capacity must be checked again before any later stage. Frozen prospective limits are 14,400 seconds cumulative, 8,400 before capture, 1,200 for export and 5,400 for one trial. Session feasibility is pending live measurements and export timing.
